- **BLOCKING** · B4's fix pins "keep the task's test files" only for a test file that already existed at `base_sha`. No case covers a test file the task creates, so an implementation that deletes new test files from the before tree passes every listed case. It then labels every case of a brand-new suite `ok-absent` (counted ok), even a case that passes on the old code.
  - Artifact text: step 6, "Every `file` path that is not the `<file>` of one of the task's `test` lines is put back to its content at `base_sha` (...); a path that did not exist at `base_sha` (`git cat-file -e <base>:<path>` fails) is deleted." (L662-665). The new case says "at `base_sha` the suite exists without case `y`" (L753). Step 7 says "A `<file>` that does not exist in a tree counts as a run with no output." (L672)
  - Evidence: I read every task-verify-tests criterion (L744-831). The fixtures with a named test file all have the suite committed before `base_sha`: mkrepo (L728-731), the new not-red case (L753), and the EU1 run, where the suite existed at `76ed77d^` because `76ed77d` only modifies it. The only "new since base" case makes the new path a non-test file (L774-775). Second strategy: `rg -n 'new since|did not exist|added with the task|new suite|new test file|brand-new|does not exist in a tree'` over the plan hits only L92, L664, L672, L749-750 and L774, and none of them is a case whose test file is new. Step 6's deletion clause sits after a semicolon with no scope, so it reads as applying to every `files:` path. Step 7's "a `<file>` that does not exist in a tree" only has a use if test files can be missing from the before tree, which supports that reading.
  - Concrete failure: suppose `verify-tests` is implemented as "for each path in `files:`: if absent at base, delete; else if not a test file, check out the base version". It passes all of L744-831, because the new not-red case catches only the revert-existing-test-file error. In real use the common shape is a task that creates its suite, as task-verify-args does with `tests/verify-tests/verify-tests.test.sh`. For such a task, every named case is absent in the before tree and labelled `ok-absent`. So a test that passes on the old code (a vacuous test) is never reported `not-red`, and `verify-tests` exits 0. That defeats the red-before check `verify-tests` exists to make, and the failure is silent.
  - Resolution: add one case, "trees: new suite file is kept in the before tree". At `base_sha` the suite file does not exist. The task's commit adds it with case `y`, which passes on the base code. The run gives `not-red`, `0 ok, 1 failed`, exit 1. An implementation that deletes new test files gives `ok-absent`. Also scope step 6's deletion clause to the same non-test paths ("such a path that did not exist..."). The reconciler may downgrade, because the most likely wrong implementation (treating test files like any other path) is now caught by L753-757. What remains open is the ordering mistake above.
